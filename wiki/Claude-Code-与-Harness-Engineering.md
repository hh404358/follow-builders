# Claude Code 与 Harness Engineering

> **摘要**：Harness Engineering 是 2026 年 AI 工程领域最核心的范式——将 LLM 的"原始能力"通过工程化外壳（Harness）转化为可靠的"产品能力"。Claude Code 是当前最完整的 Harness 实现，其 51 万行源码揭示了从权限管理、多 Agent 扩展到安全分类器的完整架构。本主题整合了 9 篇原始材料的深度分析。

## 背景：为什么需要 Harness

LLM 本身是"裸能力"——它有强大的理解和生成能力，但缺乏：
- **持久状态管理**：无法跨会话保持上下文
- **安全边界**：无法区分安全操作与危险操作
- **工具集成**：无法直接操作文件系统、API、数据库
- **多步规划**：单次推理无法完成复杂任务链

Harness 正是填补这些空缺的工程层。正如文章所言："LLM 是引擎，Harness 是底盘"。

## 核心架构分析

### 1. 权限与安全层

Claude Code 的安全架构经历了三个阶段：
- **V1**：全量人工审批（93% 通过率 → 审批疲劳）
- **V2**：Auto Mode — 基于模型的分类器审批，捕获危险操作（误删 Git 分支、上传令牌、生产库迁移）
- **V3**：Opus 4.7 的"确认-暂停"机制 — 高风险操作自动暂停请求人类确认

关键洞察：安全不是"阻止操作"，而是"在正确的时间请求正确的确认"。

### 2. 多 Agent 扩展层

源码拆解揭示了 Claude Code 的多 Agent 架构：
- **主 Agent**：负责理解用户意图和任务规划
- **子 Agent**：并行执行子任务（文件搜索、代码分析、测试运行）
- **协调器**：管理 Agent 间通信和结果聚合

这与 [[AI Agent 架构]] 中其他框架的对比见相关主题。

### 3. Token 优化策略

降低 Token 使用的 10 个有效习惯：
- 精简系统提示词，移除冗余指令
- 使用结构化输出替代自由文本
- 分阶段执行而非一次性大任务
- 缓存重复上下文
- 合理使用 `auto-compact` 自动压缩

## Harness 的本质

Harness Engineering 的核心思想：**AI 的价值不在于模型本身，而在于包裹模型的工程化外壳**。这个外壳包括：
1. **工具层**：文件操作、API 调用、代码执行
2. **安全层**：权限管理、操作审批、风险检测
3. **状态层**：上下文管理、会话持久化、记忆检索
4. **协调层**：多 Agent 调度、任务分解、结果聚合
