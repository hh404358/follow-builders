# Prompt Engineering 与 AI 工作流

> **摘要**：Prompt 不只是"给 AI 的指令"，而是人与 AI 协作的接口协议。从深度研究 Prompt 到 Vibe Writing，从 Token 优化到提示词积木公式，本主题整合 8 篇原始材料，揭示 Prompt Engineering 从"技巧"走向"工程"的演进路径。

## 背景：Prompt 为什么重要

在 [[Claude Code 与 Harness Engineering]] 的框架下，Prompt 是 Harness 的核心接口——它定义了人类意图如何被翻译为 AI 行为。Karpathy 明确指出："人类必须负责 Plan，AI 负责 Execute"。

## 核心方法论

### 1. 深度研究 Prompt

"半小时帮你搞懂任何陌生领域"的深度研究 Prompt，核心框架：
- **领域扫描**：快速建立知识地图（关键概念、核心人物、发展脉络）
- **深度钻取**：针对关键节点进行纵向深入
- **交叉验证**：多源对比，识别共识与分歧
- **结构化输出**：按"背景-方法-创新-验证-局限"框架组织

→ 这与 CLAUDE.md 中的"研究驱动，文献为锚"原则完全一致。

### 2. Vibe Writing：AI 写作的工程化流程

Vibe Writing 将软件开发流程映射到 AI 写作：

| 开发阶段 | Vibe Writing 对应 |
|---------|-----------------|
| 需求分析 | 明确读者、核心观点、风格 |
| 方案设计 | 定大纲 + 定创作规范 |
| 开发 | AI 生成初稿 |
| 测试 | 通读标 TODO → 批量修改 |
| 代码审核 | 多 AI 交叉检查准确性 |

关键原则：
- **不要逐条改**：攒一批 TODO 统一修改，避免上下文碎片化
- **融入个人经验**：确保内容不是纯 AI 味道
- **多 AI 交叉审核**：单 AI 容易过时或编造，多 AI 交叉验证避免翻车

### 3. 提示词积木公式

6 块 Prompt 积木：
1. **角色定义**：你是谁、擅长什么
2. **任务描述**：做什么、输出什么
3. **上下文提供**：背景信息、约束条件
4. **示例展示**：Few-shot 示范期望输出
5. **格式要求**：输出格式、长度限制
6. **质量标准**：评估标准、迭代方向

### 4. 用好 Agent 的核心技巧

"用好 Agent 最重要的技巧不是 Skills，是这四个字"——**上下文管理**：
- 给 Agent 足够的上下文，但不要淹没它
- 结构化输入优于自由文本
- 分阶段执行优于一次性大任务

→ 这与 [[AI Agent 架构]] 中上下文管理策略的分析一致。

### 5. Token 优化策略

降低 Token 使用的核心方法：
- 精简系统提示词，移除冗余
- 使用结构化输出替代自由文本
- 分阶段执行
- 缓存重复上下文
- 合理使用 auto-compact

### 6. Skill 分类学

"Skill 其实就是分类学"——将 AI 能力按领域、粒度、依赖关系组织为可组合的技能树。这与 [[AI Agent 架构]] 中 OpenClaw 的技能注册机制呼应。

### 7. 谷歌 AI 提示词白皮书

谷歌官方提示词核心写法：
- 系统提示词 > 少量示例 > 零样本
- 思维链（CoT）提升复杂推理
- 角色设定影响输出风格和质量

### 8. Claude Code 产品经理的 AI 工作流

Claude Code PM 分享的 AI 重构工作流：
- 将日常工作拆解为可自动化的子任务
- 用 AI 处理重复性工作，人负责决策和审核
- 建立个人 AI 工具链，而非依赖单一工具
